# STOCKROOM — Capstone Case Study

I built STOCKROOM, a mini e-commerce storefront themed as a warehouse inventory ledger, using vanilla HTML, CSS, and JavaScript with no frameworks or build tools. The app pulls live product data from the Fake Store API, and users can search by keyword, filter by category, view product detail pages, and manage a cart with quantity controls — all wired together with a lightweight hash-based router (`#/`, `#/product/:id`, `#/checkout`) so the URL always reflects the current view. The biggest technical decision was persisting the cart to `localStorage` on every mutation (add, remove, quantity change) so it survives a full page refresh, verified by reloading mid-session and confirming totals stay intact. I reused one small UI kit across the app — buttons, price/tag chips, a slide-in cart drawer, and toast notifications — instead of styling each screen separately, which kept the visual language consistent from the product grid through checkout. For polish I added staggered card entrance animations, skeleton loaders while the API call is in flight, a slide-in cart drawer, and a "stamped" confirmation screen on checkout. Given more time, I'd add proper client-side form validation with inline error states, debounce the search input to cut down on re-renders, and cache API responses so repeat visits don't re-fetch the full catalog. I'd also break the single `app.js` file into smaller modules (router, cart, views) now that the app has grown past a single-file size that's comfortable to navigate.
